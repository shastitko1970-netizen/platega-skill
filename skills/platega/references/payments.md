# Payments

Official docs.platega.io pages (re-read 2026-09-02; create pages last modified 2026-09-01):

- [Create a payment link with a specified method](https://docs.platega.io/создание-платежной-ссылки-с-заданным-методом-29203843e0.md) — `POST /transaction/process`
- [Create a payment link without a specified method](https://docs.platega.io/создание-платежной-ссылки-без-заданного-метода-33845703e0.md) — `POST /v2/transaction/process`
- [Check payment status](https://docs.platega.io/проверка-статуса-оплаты-платежа-29203844e0.md) — `GET /transaction/{id}`
- [Get QR code for an H2H transaction](https://docs.platega.io/получение-qr-кода-для-h2h-транзакции-34794775e0.md) — `GET /h2h/{id}`
- Schemas: [CreateTransactionRequest](https://docs.platega.io/createtransactionrequest-13226217d0.md), [CreateTransactionResponse](https://docs.platega.io/createtransactionresponse-13226218d0.md), [TransactionStatusResponse](https://docs.platega.io/transactionstatusresponse-13226219d0.md), [PaymentMethodInt](https://docs.platega.io/paymentmethodint-13226216d0.md), [PaymentStatus](https://docs.platega.io/paymentstatus-13226215d0.md)

Base: `https://app.platega.io/`
Auth: `X-MerchantId` + `X-Secret` (see [auth.md](auth.md)).

**Do not send field `id` on create.** Official text of both create endpoints: "Transaction ID is generated by the system automatically — do not pass field `id` in the request." Schema `CreateTransactionRequest`: "Do not specify field `id`". GitBook examples with a client UUID are stale ([legacy-gitbook.md](legacy-gitbook.md)).

**`orderId` (optional, added 2026-09-01).** Both `POST /transaction/process` and `POST /v2/transaction/process` now document `orderId` as a string: "ID вашего внутреннего платежа" / "ID of your internal payment". It is listed in `x-apidog-orders`, **not** in OpenAPI `required`. Official examples still omit it. The standalone `CreateTransactionRequest` schema (as of 2026-09-02) still has no `orderId` and `additionalProperties: false` — same lag as `metadata`. Follow the **endpoint** OpenAPI, not the shared schema. Docs do **not** say `orderId` is echoed as `externalId` on status; do not invent that mapping. Subscription create OpenAPI still has no `orderId`.

`POST /transaction/process` also creates a **subscription** if `paymentMethod` is `6`. That is not a `PaymentMethodInt` method. See [subscriptions.md](subscriptions.md).

## Payment methods (current PaymentMethodInt)

Official `PaymentMethodInt` enum:

| int | Schema name | Name in response (example) |
| --- | --- | --- |
| `2` | SBP (QR code) | `SBPQR` |
| `3` | ERIP | — |
| `11` | Card acquiring | — |
| `12` | International payment | — |
| `13` | Cryptocurrency | — |
| `14` | Sberpay | — |

Outside this table:

| int | Where | Notes |
| --- | --- | --- |
| `6` | Create subscription | Always number `6`, not a string. Not in `PaymentMethodInt`. |
| `10` | GitBook CardRu | "Card 2dcs, MIR card payments". Not in the current schema. |
| `1`–`9` | GitBook P2P | "All other methods, including method 1, 2–9, are related to P2P". Conflict: `2` in current docs is SBP QR. |

### Crypto (`13`)

By default the user goes to the **web payform**. Payment via Telegram bot — contact the manager.

### Metadata / antifraud

Stores in some categories must send `metadata` with a payer identifier. Confirm with the manager.

Missing **`metadata.userId`** when it is required disables antifraud and **may disable the store**.

In create examples (both endpoints) `metadata` contains `userId`, `userName`, `clientIp`. In the OpenAPI `metadata` object, required fields are `userId` and `userName`; `clientIp` is in the example, not in schema properties.

## POST `/transaction/process` — link with a specified method

`operationId`: `createTransaction`

### Headers

| Header | Required |
| --- | --- |
| `X-MerchantId` | yes |
| `X-Secret` | yes |

`Content-Type: application/json` is implied (JSON API).

### Body

Per OpenAPI of **this** endpoint, `required`: `paymentMethod`, `paymentDetails`, `description`, `return`, `failedUrl`.

The standalone `CreateTransactionRequest` schema requires only `paymentMethod` + `paymentDetails` and describes the rest as optional. For a **payment** call, follow the endpoint required set (five fields). For a **subscription**, required fields differ — see [subscriptions.md](subscriptions.md).

| Field | Type | Required (payment endpoint) | Description |
| --- | --- | --- | --- |
| `paymentMethod` | integer (`PaymentMethodInt`) | yes | `2`, `3`, `11`, `12`, `13`, `14` |
| `paymentDetails` | object | yes | |
| `paymentDetails.amount` | number | yes | Amount |
| `paymentDetails.currency` | string | yes | e.g. `RUB` |
| `description` | string | yes | Purpose. Schema: "include whenever possible" |
| `return` | string (uri) | yes | Redirect on success |
| `failedUrl` | string (uri) | yes | Redirect on failure |
| `payload` | string | no | Extra info for your system |
| `orderId` | string | no | Your internal payment ID (endpoint OpenAPI since 2026-09-01; not in shared `CreateTransactionRequest`) |
| `metadata` | object | no* | *required for some categories |
| `metadata.userId` | string | if metadata present | Unique payer ID (e.g. Telegram user ID), antifraud |
| `metadata.userName` | string | if metadata present | Extra payer data |
| `id` | — | **do not send** | System-generated transaction ID. Not the same as `orderId` |

### 200 response — `CreateTransactionResponse`

Schema required: `transactionId`, `status`.

| Field | Type | Description |
| --- | --- | --- |
| `paymentMethod` | string | Human-readable name (schema: "e.g. 2"; example: `SBPQR`) |
| `transactionId` | string (uuid) | Created transaction ID |
| `redirect` | string (uri) | Payment URL |
| `return` | string (uri) | Your success redirect |
| `paymentDetails` | string **or** `{amount, currency}` | Example is string `"100 RUB"` |
| `status` | `PaymentStatus` | Usually `PENDING` |
| `expiresIn` | string | Time until expiry `HH:MM:SS` (example `00:15:00`) |
| `merchantId` | string (uuid) | |
| `usdtRate` | number (float) | USDT conversion rate at payment time (GitBook comment on the same field) |

### Errors

| HTTP | OpenAPI description |
| --- | --- |
| `400` | Request validation error |
| `401` | Auth error (check X-MerchantId / X-Secret) |

GitBook 400 for P2P (not in current OpenAPI): `No available requisites`, `Transaction … already exists` — [legacy-gitbook.md](legacy-gitbook.md).

### Example

```http
POST /transaction/process HTTP/1.1
Host: app.platega.io
Content-Type: application/json
X-MerchantId: 1a021d91-9b26-4762-b303-5d4aac74e921
X-Secret: <secret>
```

```json
{
  "paymentMethod": 2,
  "paymentDetails": {
    "amount": 500,
    "currency": "RUB"
  },
  "description": "Оплата мешков картошки клиенту №293",
  "return": "https://google.com/success",
  "failedUrl": "https://google.com/fail",
  "payload": "Дополнительная информация о платеже",
  "orderId": "shop-order-293",
  "metadata": {
    "userId": "123456789",
    "userName": "@username",
    "clientIp": "111.47.86.11"
  }
}
```

`orderId` is optional; the official example still omits it. Shown here so agents do not stuff the same value into `id`.

Response (official example):

```json
{
  "paymentMethod": "SBPQR",
  "transactionId": "3fa85f64-5717-4562-b3fc-2c463f66afa6",
  "redirect": "https://pay.platega.io?qrsbp",
  "return": "https://google.com",
  "paymentDetails": "100 RUB",
  "status": "PENDING",
  "expiresIn": "00:15:00",
  "merchantId": "1a021d91-9b26-4762-b303-5d4aac74e921",
  "usdtRate": 93.45
}
```

Send the payer to `redirect`.

## POST `/v2/transaction/process` — no specified method

The payer picks a method on the hosted page.

`operationId` in OpenAPI is also `createTransaction` (name collision with v1).

### Headers

Same: `X-MerchantId`, `X-Secret` (required).

### Body

**No** `paymentMethod`. Required: `paymentDetails`, `description`, `return`, `failedUrl`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `paymentDetails.amount` | number | yes | |
| `paymentDetails.currency` | string | yes | |
| `description` | string | yes | |
| `return` | string | yes | Success URL |
| `failedUrl` | string | yes | Fail URL |
| `payload` | string | no | |
| `orderId` | string | no | Same as v1: your internal payment ID, not system `id` |
| `metadata.userId` / `userName` | string | if you send metadata | Same antifraud rules |
| `id` | — | **do not send** | |

Text about `paymentMethod: 13` / Telegram bot is also on this page even though the request has no method (copied description).

### 200 response

Required: `transactionId`, `status`, `url`, `expiresIn`, `rate`.

| Field | Type | vs v1 |
| --- | --- | --- |
| `transactionId` | string | same |
| `status` | string | same |
| `url` | string | **not** `redirect` |
| `expiresIn` | string | same |
| `rate` | number | **not** `usdtRate` |

No `paymentMethod`, `redirect`, `return`, `paymentDetails`, `merchantId` in the v2 response schema.

### Errors

`400` validation, `401` auth.

### Example

```json
{
  "paymentDetails": {
    "amount": 500,
    "currency": "RUB"
  },
  "description": "Оплата мешков картошки клиенту №293",
  "return": "https://google.com/success",
  "failedUrl": "https://google.com/fail",
  "payload": "Дополнительная информация о платеже",
  "metadata": {
    "userId": "123456789",
    "userName": "@username",
    "clientIp": "111.47.86.11"
  }
}
```

```json
{
  "transactionId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "status": "PENDING",
  "url": "https://pay.platega.io/?id=f8000067-a4a0-0000-0000-2556a0b40000&mh=0a0000a4-0000-0000-0000-200004060000",
  "expiresIn": "00:15:00",
  "rate": 91.2
}
```

Send the payer to `url`.

## GET `/h2h/{id}` — H2H QR / link

"If you want to accept payments in H2H mode — contact your manager to enable it."

`operationId` in OpenAPI is again `createTransaction` (name collision).

### Parameters

| Name | In | Required |
| --- | --- | --- |
| `id` | path (transaction uuid) | yes |
| `X-MerchantId` | header | yes |
| `X-Secret` | header | yes |

### 200 response (current docs)

Required: `amount`, `qr`.

| Field | Type |
| --- | --- |
| `amount` | number |
| `qr` | string (example — URL `https://qr.nspk.ru/...`) |

```json
{
  "amount": 136.12,
  "qr": "https://qr.nspk.ru/00000000000000000000000000?type=00&bank=000000000000&sum=00000&cur=RUB&crc=0000"
}
```

### Errors

| HTTP | OpenAPI description |
| --- | --- |
| `400` | Transaction not found |

(On payment status, "not found" is `404`. Here the spec says `400`.)

### GitBook H2H (conflict)

GitBook "Create H2H payment — return requisites" describes a different JSON: `accountNumber`, `maskedAccountNumber`, `accountName`, `method`, `amount`. See [legacy-gitbook.md](legacy-gitbook.md). By default for a current integration use `{amount, qr}`.

## Payment statuses

Official `PaymentStatus`: `PENDING`, `CANCELED`, `CONFIRMED`, `CHARGEBACKED`.

Payment callback schema enum is only `CONFIRMED` and `CANCELED`, but the prose on the same page adds `CHARGEBACKED` on refund. See [callbacks.md](callbacks.md).

---

## Practical sequence

1. Create a transaction (v1 with a method or v2 without).
2. Store `transactionId` from the response (not from the request).
3. Send the payer to `redirect` (v1) or `url` (v2).
4. For H2H: after create call `GET /h2h/{transactionId}`.
5. Wait for callback and/or poll `GET /transaction/{id}`.
6. Build accounting idempotency on `transactionId`, not a client UUID.
