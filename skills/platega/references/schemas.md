## CreateTransactionRequest

`additionalProperties: false`. Description: "Request body for creating a transaction. **Do not specify field `id` — it is generated by the system automatically.**"

Schema required: `paymentMethod`, `paymentDetails`.

| Field | Type | Required | Schema description |
| --- | --- | --- | --- |
| `paymentMethod` | `PaymentMethodInt` | yes | "Payment method number (e.g. 2 for SBP QR)" |
| `paymentDetails` | object, additionalProperties false | yes | |
| `paymentDetails.amount` | number (float) | yes | Payment amount |
| `paymentDetails.currency` | string | yes | Currency (e.g. RUB) |
| `description` | string | no | "Payment purpose (description), include whenever possible" |
| `return` | string (uri) | no | Redirect on successful payment |
| `failedUrl` | string (uri) | no | Redirect on failed payment |
| `payload` | string | no | "Extra information for initialization in your system." |

Field `metadata` is absent from **this** schema (it exists in create-endpoint OpenAPI).
Required set of `POST /transaction/process` (payment) is wider: + `description`, `return`, `failedUrl`.
The schema does not cover subscriptions (`interval`, `paymentMethod: 6`).

## SubscriptionStatus

`type: string`. "Subscription status".

| Value | Description in x-apidog-enum |
| --- | --- |
| `PendingAgreement` | (empty) |
| `Active` | (empty) |
| `PastDue` | (empty) |
| `Cancelled` | (empty) |
| `Failed` | (empty) |

GET one subscription returns these strings (`Active`). Subscription list returns `status` as an **integer** (example `4`) — mapping is not defined in this schema.

Cancel example: `"status": "cancelled"` (lowercase) — not an enum value.

## SubscriptionInterval

`type: string`. "Subscription billing interval".

| value | description |
| --- | --- |
| `'1'` | (empty; create prose: day) |
| `'2'` | (empty; create prose: week) |
| `'3'` | `30 дней` (create prose: month) |
| `'4'` | (empty; create prose: year) |

Create example sends integer `3`. `intervalCount` limits (day ≤31, week ≤4, month ≤12, year ≤3) live in create prose, not in this schema.

## CallbackSubscriptionStatus

`type: string`. "Subscription status in Callback".

| Value | Description |
| --- | --- |
| `SUBSCRIPTION_ACTIVATED` | Subscription is active, charges run on schedule |
| `SUBSCRIPTION_PAST_DUE` | Permanent; no transitions out unless there is a webhook of a successful payment or a cancel |
| `SUBSCRIPTION_CANCELLED` | Transition from ACTIVATED or PAST_DUE — explicit cancel by merchant or payer (cancel link or API) |
| `SUBSCRIPTION_FAILED` | Transition from ACTIVATED — bind failed at first activation (provider returned an error or did not confirm consent) |

This is not `SubscriptionStatus` and not `PaymentStatus`.

## CallbackPayload

`additionalProperties: false`. Required: `id`, `amount`, `currency`, `status`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | uuid | yes | transaction ID |
| `amount` | number (float) | yes | |
| `currency` | string | yes | |
| `status` | string enum `CONFIRMED` \| `CANCELED` | yes | "Transaction status in callback" |
| `paymentMethod` | integer | no | payment method ID |

Payment callback page prose additionally names `CHARGEBACKED`. Field `payload` is not in this schema (it exists in the payment webhook OpenAPI).

Subscription callbacks are **not** this object: PascalCase + `SubscriptionId` + `NextChargeAt`.
